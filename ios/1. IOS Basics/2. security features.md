IOS have a hardware and software security features
#### Hardware security features
Hardware security security on the chipset such:
-  Hardware Root of Trust
	- Security begins in hardware using an **immutable Boot ROM** (burned during chip fabrication).
	- Boot ROM ensures **only Apple-trusted code** loads during startup (Secure Boot).
- Secure Enclave
	- processor Dedicated silicon within the SoC(system on chip) for:
	    - Key generation, storage, and management.
	    - Processing biometric authentication (Face ID, Touch ID, Optic ID).
	    - Running its own **boot process** and OS, isolated from the main OS.
	- **Communication channel** ensures key material is **never exposed to the CPU or OS**.
-  File Encryption
	- File contents are **automatically encrypted** using the **AES engine**.
	- Encryption happens **in-line** during file read/write, using keys provided by the Secure Enclave.
-  **Data Protection Classes** (iOS File Encryption Model)
	- every file encrypted with it's own uniq key, generated from Hardware key and passcode 
	- Define **when and how** data is accessible:
	
	| Class                                                    | Description                                                                |
	| -------------------------------------------------------- | -------------------------------------------------------------------------- |
	| **NSFileProtectionComplete**                             | Data is accessible **only when device is unlocked**. Strongest protection. |
	| **NSFileProtectionCompleteUntilFirstUserAuthentication** | Data is available after first unlock until shutdown.                       |
	| **NSFileProtectionCompleteUnlessOpen**                   | File stays accessible while open, even if device locks.                    |
	| **NSFileProtectionNone**                                 | No protection – data always accessible (least secure).                     |
- Data Execution Prevention
	Memory is divided into two parts executable and writeable
	The user is allowed only to write data inside the specified writable range but can't e.g execute shellcode in it
	The code to be executed is only located inside the executable area, the Operating System only can access the executable area and write in it

#### Software security features
- App Sandbox
	- Each app runs in a **restricted container**:
	    - No access to other apps’ data or system files.
		    - `# /private/var/mobile/Containers/Bundle/Application/` holds the Application folder
	    - Limits access to hardware and OS services (unless explicitly granted).
	- Apps must declare permissions for camera, location, contacts, etc.
	- https://theapplewiki.com/wiki/Filesystem:/private/var/mobile/Containers/Bundle/Application
- System Integrity Protection
	- **Code Signing**: All executables must be signed by Apple and an authorized developer.
	- Prevents execution of unverified or modified code.
	- any application without signing will not run on iOS, this is only possible while connecting the mobile and building the application directly on it

- System Updates
	- Apple delivers **timely and full-device security updates** across its device lineup.
	- All devices receive the **same build** to avoid fragmentation and missed patches.
	- for a critical vuln apple can **enforce updates**
- Secure Boot Chain
	- Ensures **only trusted Apple-signed software** runs at each stage of boot (Boot ROM → LLB → iBoot → kernel).
	- Every stage verifies the signature of the next using certificate, preventing tampering.
	- **BootROM** stage
		- where The BootROM contains the initial bootloader and Apple's root certificate, which it uses to verify the signature of the next stage in the boot process (Low-Level Bootloader or iBoot; based on version)
		- If signature validation fails (e.g., due to tampered or unsigned firmware), the device enters Device Firmware Upgrade (DFU) mode or a recovery mode
		- Since BootROM is immutable, any vulnerability (like the famous Checkm8 exploit) is a hardware-level flaw that cannot be patched via software updates.
		- exploit Checkm8 reqiures physical access , such USB
	- **Low-Level Bootloader (LLB)**
		The LLB was part of the boot chain in early iOS versions (pre-iOS 5)
	- **iBoot**
		- iBoot is the primary bootloader in modern iOS devices, responsible for loading the iOS kernel and initializing critical system components.
		- supports multiple boot modes, such as normal boot, recovery mode, or DFU mode, depending on the device's state or user input (e.g., pressing specific buttons during startup).
		- Unlike BootROM, kernel flaws are software-based and fixable.
		- Unlike BootROM, iBoot can be updated via firmware updates, allowing Apple to patch vulnerabilities in newer devices.
	- **Kernel**
		- XNU based on Darwin, mange system processes: hardware access, memory mang,..
		- Exploits like those used in jailbreaking (e.g., unc0ver or Chimera) often target kernel vulnerabilities to disable code signing or bypass sandbox restrictions.
