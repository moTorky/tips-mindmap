can be done using: 
1. URL Schemes: 
	-  more similar to android deep link, where an url associate to app  
	- URL scehme for the aplication to be called should be configured on both the caller and the called
	- This had a problem if two applications have the both URL scheme, the latest one can be called instead of the intended application
2. Universal Links
	-  use https:// schema, this URL has to be defined in the Universal Links
	- The Universal Links are defined inside the application itself in apple-app-site-association file and stored in JSON format under .well-known subdirectory
	- This is to be handled by the iOS as the iOS will redirect the user to this link 
3. pasteboard:
	- allow apps to share small bit of data such text or image
4. app group and shared containers:
	- think about apps signed with same certificate 
5. XPC services (Cross-Process Communication)
	- a layer between apps(process) where apps can communicate between each other
	- cuz it's a service: it's implemented on the app, like android 
	- if XPC service not handle user input -> it could lead to command injection,
